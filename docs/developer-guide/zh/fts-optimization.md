# 全文索引热路径优化记录

修改前版本：`5bce9e06d`。本轮按要求不编译、不启动新版本、不运行性能基准。

## 源码定位依据与修改

| 路径 | 修改前的重复工作 | 修改后 |
| --- | --- | --- |
| IK `ObFTCharUtil::do_classify` | 各类别判断分别解码同一字符；UTF-8 英文字母解码 1 次、数字 2 次、汉字 3 次、其他字符最多 4 次 | 每次分类解码 1 次，保留原判断顺序、Unicode 范围和错误返回 |
| IK `ObIKFTParser::process_one_char` | 主循环读取字符信息后，四个处理器各调用两个 getter 再读一次 | 把已读取的字符指针、长度和类别传给处理器，省去每字符 8 次重复 getter 调用，保留处理器顺序 |
| BENG `ObBasicEnglishNormalizer::get_next` | 每个词重置 arena 并为小写转换分配缓冲区 | 复用归一化缓冲区，容量不足时释放旧空间并重新分配；`reset()` 释放，`reuse()` 保留以复用 |

以上属于源码层面的优化依据，不是 CPU profile 或耗时测量结果。IK 分类也用于仲裁输出，因此分类优化同时覆盖该路径。两类分词器由索引构建、TOKENIZE 和查询词解析共用，最终对各计分项的收益取决于分词在实际执行中的占比。

BENG 继续使用原字符集的 `casedn` 函数，保持 `ObCharset::tolower` 的原地转换和扩展转换两种调用方式。输出缓冲区在下一次取词时可被覆盖；BENG 解析器原有的逐词复制保留，避免倒排词表持有可被覆盖的缓冲区。内存按所见最长词保留到归一化器重置或销毁，这是减少分配次数的空间权衡。

未修改公共排序、存储写入、分词规则、词典、停用词规则或评测文件。

## 正确性验证

新增现有 mysqltest 套件中的 `fts_index.fts_hotpath`，包含：

- IK smart/max_word 的完整词集合比较，既有 `cn_word.result` 提供中文分词预期。
- 英文、数字、中文、日文、韩文、全角字符和 emoji 的分类行为，以及跨越 IK 批次边界的词频检查。
- BENG 缓冲区扩容、长短词交替、非 ASCII 小写转换、重复词频和纯标点输入。
- 导入后构建 IK/BENG 索引、在线插入、MATCH 完整有序 ID、混合查询及 LIMIT。
- 更新和删除后的索引结果。

词集合采用双向 JSON_CONTAINS 比较，避免依赖哈希表遍历顺序；词频用完整 `output=all` 对象核对。

本轮完成的非编译检查：

- `git diff --check`。
- 从源码提取原、新类别判断顺序及 Unicode 范围，对全部 1,114,112 个码点检查 UTF-8/UTF-16 分类谓词等价。这不执行 C++ 解码器，也不替代异常输入或运行回归。
- 回归用例预期 JSON 格式检查，以及现有 mysqltest runner 的用例发现检查。

上述 SQL 回归和对应结果文件尚未在数据库上执行核对。当前会话的本地数据库探测返回 `Can't create TCP/IP socket`，不能据此判断数据库是否已启动。

## 编译后的验证顺序

1. 编译和链接：确认 C++ 类型、模板、头文件依赖和链接符号正确，生成包含改动的可执行文件。
2. 用新可执行文件启动专用测试实例，执行 `fts_index.fts_hotpath`，再执行现有 `fts_index` 套件。新旧版本均应通过这些正确性检查；不能仅更新预期结果消除失败。
3. 在相同环境、相同编译配置下分别运行修改前后版本的完整官方基准，每次使用新报告文件，保持 `SKIP_LOAD=0` 和固定参数。
